# 1.1.0 (2026-11-13)

## Breaking
- none

## Added
- npmjs publication workflow and policy: `publish.yml` (name `Publish`) runs a GitHub Packages job and an npmjs job that uses OIDC (`id-token: write`), the `npm-publish` environment, and `npm stage publish`; the npmjs registry is primary and GitHub Packages is the mirror (a95e08b).
- Staged publishing through a GitHub Actions trusted publisher, with a maintainer approving the staged version on npmjs.com with 2FA; the agent never runs a registry mutation (a95e08b, 9cf0e8f).
- Color output and the read-only publish checker: a dependency-free ANSI helper that disables itself for a non-TTY stream, `NO_COLOR`, or `TERM=dumb`, and `pnpm publish:npm`, which validates the package and prints the exact command without running it (9cf0e8f).
- Branch-per-prompt: every orchestrator prompt starts with `git branch --show-current` and creates `task/<task-slug>` from the default branch when on `main` or a detached HEAD (a92eeae).
- Delegation worktrees: each delegated task runs in `.worktrees/<task-slug>-<subtask>` on its own sub-branch with an explicit allowed-file list, merges back with `git merge --no-ff`, and is removed only when merged and clean (a92eeae, 76de2b2).
- Worktree permissions and the in-project worktree rule: `opencode.json` allows `/tmp`, `/var/tmp`, and `.worktrees`, and every task requires an in-project worktree (4b81af9, 9ef5575).
- PR-only authority and single-use approvals: the orchestrator's authority ends at `gh pr create`; it never merges, uses `--admin`, pushes `main`, force-pushes, tags, or rebases/resets `main`, and every approval covers one command exactly once (7bf38ef, ffe3e9f, 53caa58).
- Environment setup and design bootstrap: the orchestrator resolves the project root and CLIs before boot, and the design registry always writes a project-wide map at `docs/design/other/project.md`; `docs/RECONCILE.md` installs as a shared doc (e98b71c, 3171f24, 1091001, 6ba07b5).
