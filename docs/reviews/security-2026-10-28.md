## Method

1. Rule scan over every text file for secrets, `eval`, shell strings, unsafe `rm`, curl-pipe-shell, publish and tag commands, TLS disabled, CORS wildcard.
2. Manual read of the high-risk code and CI files: `src/install-external.js`, `.github/workflows/release.yml`, `README.md`, `package.json`.

## [high] Shell injection in the external installer

Where: src/install-external.js:59, 67, 68
Why it matters: the `--agent` value from the command line is placed in a shell string that `bash -c` interprets, and `$(...)` expands inside it. Skill names and sources from skills-lock.json take the same path.
Evidence: replicated the installer's quoting with a harmless marker command. Passing `--agent 'x$(touch /tmp/opencode/INJECTED)y'` created the marker file. The injected command ran.
Suggested fix: do not build a shell string. Spawn `script` with an argument array, or drop the PTY hack and pass the answer through a supported non-interactive flag. Never interpolate.

## [high] Script injection through a workflow input

Where: .github/workflows/release.yml:60
Why it matters: `${{ github.event.inputs.version }}` is substituted directly into a `run:` shell script. Anyone with write access can dispatch the workflow with a crafted version, and that text runs with `contents: write` and `id-token: write`.
Evidence: `run: npm version ${{ github.event.inputs.version }} --no-git-tag-version`
Suggested fix: pass the input through `env:` and quote it in the shell, for example `env: VERSION: ${{ github.event.inputs.version }}` then `npm version "$VERSION"`. Validate it against a semver pattern.

## [medium] Third-party actions are not pinned to a commit

Where: .github/workflows/release.yml:22, 28, 44, 50, 67; .github/workflows/ci.yml:10, 14, 17
Why it matters: `actions/checkout@v4`, `pnpm/action-setup@v4`, `softprops/action-gh-release@v2` are mutable tags. The release job holds `id-token: write` and `contents: write`.
Evidence: tag references above.
Suggested fix: pin each to a full commit SHA with the tag in a comment. Keep the release job's permissions to the minimum it needs.

## [low] Workflow-wide write permissions

Where: .github/workflows/release.yml:14-16
Why it matters: `contents: write` and `id-token: write` apply to every job, including `test`, which runs untrusted pull request code under CI.
Evidence: top-level `permissions:` block.
Suggested fix: set `permissions: contents: read` at the top, and grant write permissions only on the `publish` job.

## [medium] Library cannot reach any agent

Where: src/guide.js:16, 22, 201-204 (reads library/ only to print names). No code copies library/ into an agent directory. Checked: no `orchestrator`, `route`, or library agent exists in `~/.agents/skills` or `~/.config/opencode/agent`.
Why it matters: the orchestrator's Discovery step and every routing rule assume the library is installed. As shipped, the orchestrator is not loadable by an agent, so the central design does not work end to end.
Evidence: grep of src and bin for install or copy logic that targets agent directories returns none.
Suggested fix: decide where agents load the library from (copy into the agent's config directory, or symlink, with an explicit install step). Record the decision in docs/decisions/. Then add a test that the installed layout matches what the orchestrator expects.

## [medium] Install commands name a source that does not exist

Where: README.md:8, 10; src/guide.js:151-152
Why it matters: `npx skills add junamis-skills` and `npx skillsio add junamis-skills` are not valid sources. A new user copying them gets a failed install.
Evidence: `skillsio add devenius/junamis-skills --list` resolves the GitHub repo, so the correct source is `devenius/junamis-skills`.
Suggested fix: replace `junamis-skills` with `devenius/junamis-skills` in both files. After publishing, consider also documenting `npx junamis-skills install-external`.

## [medium] Remote lists fewer library skills than exist locally

Where: GitHub listing of devenius/junamis-skills (the pushed commit 8789d47)
Why it matters: `skillsio add devenius/junamis-skills --list` returned 11 skills. The pushed commit contains more library skills than that. The cause is not determined.
Evidence: the returned list was db-migrate, decision-record, dependency-upgrade, deploy-verify, env-doctor, handoff, refactor-safely, release-prep, rollback, route, skill-author. Missing: incident-response, perf-budget, research, security-audit.
Suggested fix: confirm after the next push that the list matches `library/skills/`. Do not publish until it does.

## [low] Installer and CI paths have no tests

Where: src/install-external.js and scripts/check-skills-sync.mjs (no test file); .github/workflows/* (not validated by any test)
Why it matters: the injection above went unnoticed because nothing exercises that code path.
Suggested fix: add a unit test that feeds hostile agent and source values and asserts nothing is executed. Add a workflow lint step (for example actionlint) to CI.

## Non-security defects found during the scan

- **[high] CI pins the wrong pnpm.** `.github/workflows/ci.yml:17` and `.github/workflows/release.yml:26, 48` use `version: 10`. `package.json:34` sets `packageManager: pnpm@12.15.0`. `pnpm/action-setup` refuses a version that disagrees with `packageManager`, so CI is expected to fail on the first run. Not run; confirm on the first push. Fix: use the `packageManager` value and drop the explicit version, or change `packageManager` to match.
- **[medium] Stale external list in the route skill.** `library/skills/route/SKILL.md:42` lists only `debug`, `architect`, `develop` as external. The orchestrator lists about fourteen. Fix: point both at one list, or reference `library/EXTERNAL.md`.
- **[low] Version record out of step.** `CHANGELOG.md` section 1.0.0 says "24 external skills", which described the state at release time, but the Unreleased section does not say the count changed. Fix: state the current count (24) in Unreleased.
- **[low] Release tag can disagree with package.json.** The publish job runs `npm version` only when the input is set. Pushing a tag `v1.0.1` while `package.json` says `1.0.0` publishes 1.0.0 again, which npm rejects. Fix: fail the job if the tag does not equal the package version.
- **[info] Unpushed commit.** Local `main` is 1 commit ahead of `origin/main` (173bd38). It includes the workflow files and the new skills. It was not pushed. Review it before any push.
